Adds a "Granola" button to the composer toolbar when you start a new chat: in a new agent's composer and on the New workspace screen. It is hidden in the composer of an agent that is already running. It opens a meeting picker; choosing a meeting attaches its transcript to the message as a Markdown document, shown as a pill above the composer. The document has the meeting title, date, owner, attendees, a link to the note, Granola's summary, and the full transcript with speaker names and timestamps. The same attachment is also available as "Granola" in the composer's "+" menu, with a plain search list.

The picker lists meetings with their date, time, and owner. Search matches meeting titles and Granola summaries. Filter by space, folder (including its subfolders), team member (chosen from the attendees of the 60 most recent meetings in the current filters, most frequent first; a team member owns one of the listed notes or shares a company email domain with an owner, so external guests are left out), and meeting date: the last 7, 30, or 90 days, or any time. Sort by newest or oldest meeting, or by recently updated. Space, folder, participant, date, and sort choices are remembered on each device. Space and folder filters only appear when the API key can see spaces or folders.

## Setup

Requires Paseo 0.16.0-beta.1 or later on both the app and the daemon, and a Granola Business or Enterprise plan. Create an API key in Granola under Settings → API, then paste it in Settings → Plugins → Granola. If no key is saved, the plugin falls back to the `GRANOLA_API_KEY` environment variable of the daemon. The same settings page turns the summary on or off.

## What it sends and stores

Requests go from the daemon to `public-api.granola.ai` using your API key, and only read data. The key is stored in this host's plugin settings as plain JSON, not in a credential vault.

The Granola API only returns notes shared in a workspace-wide folder or in a space with API access, and only after Granola has finished processing them. A workspace admin can turn off transcript access over the API. Search and participant filters use Granola's search index, which covers titles and summaries but not transcripts; without a search term the picker lists notes directly. If the key cannot use search, the picker matches titles and owners from the list instead. Lists show up to 50 meetings. Meeting lists are cached for one minute and transcripts for ten minutes, in memory. Spaces, folders, and each meeting's attendees are also saved to `~/.paseo/granola/cache.json` (or under `PASEO_HOME`), grouped by a hash of the API key, so they survive restarts: spaces and folders show at once and refresh in the background after 15 minutes, and attendees are fetched again only when a meeting changes. The "+" menu fetches transcripts for its top 8 matches.
